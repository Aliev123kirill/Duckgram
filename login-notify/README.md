# Dogram Login Notify

Связка клиента Duckgram с ботом оповещений о входе. Добавляет в приложение
только отправку события «пользователь вошёл»; интерфейс и `dist` не изменяются.

## Что изменено в приложении

| Файл | Изменение |
|---|---|
| `electron/main.js` | + блок `login-notify` (конфиг, POST, IPC, вставка скрипта в index.html в памяти) |
| `electron/preload.js` | + `electronHelpers.notifyLogin(payload)` |
| `login-notify/renderer.js` | новый: определяет вход и вызывает `notifyLogin` |
| `login-notify/config.json` | новый: адрес сервера бота и секрет |

Исходные `main.js` и `preload.js` сохранены в `backup/`.
Откат: запустить `uninstall.cmd`.

## Как это работает

1. `main.js` при старте находит в `dist` модуль tweb с `rootScope.getMyId()`.
2. В `index.html` (только в памяти, файл на диске не меняется) добавляется
   `<script type="module" src="/duckgram-login-notify.js">`.
3. Скрипт ждёт, пока интерфейс покажет чаты вместо экрана входа, и сравнивает
   `rootScope.getMyId()` с сохранённым в `localStorage`.
4. Если ID новый (первый вход, смена аккаунта или вход после выхода) —
   вызывается `electronHelpers.notifyLogin({ userId, device })`.
5. `main.js` отправляет `POST /api/login` на сервер бота с заголовком
   `x-dogram-secret`. Сеть — из main-процесса, поэтому CORS не мешает.
6. Если сервер ответил `userHasBot: false` (бот ещё не знаком с аккаунтом),
   клиент сам отправляет боту `/start` через API Telegram — от имени
   пользователя, как при открытии чата с ботом. Бот отвечает приветствием,
   а отложенное событие входа доставляется сразу.

Повторные уведомления при обычном перезапуске приложения не отправляются:
ID запоминается. При выходе из аккаунта метка стирается.

## Настройка

`config.json`:

```json
{
  "enabled": true,
  "url": "http://127.0.0.1:8787/api/login",
  "secret": "ваш LOGIN_SECRET из .env бота",
  "botUsername": "DUCKGRAM_NOTIFY_bot",
  "dedupeSeconds": 120
}
```

- `url` — адрес сервера бота (можно `https://...`, если бот на VPS).
- `secret` — тот же `LOGIN_SECRET`, что в `.env` бота.
- `botUsername` — имя бота без `@`, которому клиент отправляет `/start`.
- `dedupeSeconds` — защита от случайного двойного события.

Перезапуск Duckgram после изменения конфига не обязателен: файл читается
при каждом событии.

## Проверка

1. Запустить бота: `D:\My work\dogram-login-bot\start.bat`.
2. Запустить Duckgram и войти в аккаунт (или выйти и войти снова).
3. В окне бота должно появиться сообщение о входе.

Логи приложения: `%APPDATA%\tweb\debug.log`, строки `[login-notify] ...`.

Если Telegram недоступен с этого компьютера, бот не сможет отправить
сообщение — событие всё равно дойдёт до сервера и будет видно в его логе.
